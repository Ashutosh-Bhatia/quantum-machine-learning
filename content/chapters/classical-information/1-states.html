Before asking what makes a quantum computer different, we need a language for describing a system, the information it stores, and the operations we can perform on it. We can develop that language using familiar classical systems.

1. A system and its possible states

Consider a device that we want to describe. A bit can have value 0 or 1. A die resting on a table can show one of six upper faces. A simplified fan switch can have three settings: off, low, or high. The first modelling decision is to choose which distinctions matter for our task.

We call the collection of possible classical states the state set, denoted by \(\Sigma\). For the examples above,

\[\Sigma_{\mathrm{bit}}=\{0,1\},\qquad \Sigma_{\mathrm{die}}=\{1,2,3,4,5,6\},\qquad \Sigma_{\mathrm{switch}}=\{\mathrm{off},\mathrm{low},\mathrm{high}\}.\]

These are models of the devices. A real fan also has a temperature, a rotor speed, and many other properties. If the question is only which setting has been selected, the three-state description is sufficient. If we want to predict the motor's dynamics, it is not. A state description is always tied to the question and level of abstraction.

A state label is part of a model.

The symbol “high” identifies one setting. It does not describe every microscopic detail of the fan, and renaming it does not change the physical device.

2. Choosing labels and an order

Suppose our switch is definitely set to low. We can record that fact with the label “low.” But calculations become easier if all state descriptions have a common mathematical form. We therefore place the state labels in a fixed order and associate one coordinate with each label.

Choose the order \((\mathrm{off},\mathrm{low},\mathrm{high})\). The coordinate corresponding to the actual state will be 1; all other coordinates will be 0. This is a one-hot representation. The three coordinate vectors are

\[e_{\mathrm{off}}=\begin{pmatrix}1\\0\\0\end{pmatrix},\qquad e_{\mathrm{low}}=\begin{pmatrix}0\\1\\0\end{pmatrix},\qquad e_{\mathrm{high}}=\begin{pmatrix}0\\0\\1\end{pmatrix}.\]

The order is a convention, not an extra physical property. If we instead choose \((\mathrm{high},\mathrm{off},\mathrm{low})\), the same setting low is represented by \((0,0,1)^{\mathsf T}\). Its position changed because we reordered our coordinates. Its meaning did not change.

This distinction will matter throughout the course: a coordinate vector can only be interpreted when its basis order is known. Later, multi-qubit circuit diagrams and software will introduce further ordering conventions. We start the habit of writing the order now.

3. Standard basis vectors and ket notation

For a state set with \(d\) labels, there are \(d\) standard coordinate vectors. The vector for label \(a\) has a 1 at position \(a\) and zeros elsewhere. These vectors form the standard basis: any \(d\)-component vector can be written uniquely as a weighted sum of them.

For example, a vector \(v=(v_{\mathrm{off}},v_{\mathrm{low}},v_{\mathrm{high}})^{\mathsf T}\) can be written as

\[v=v_{\mathrm{off}}e_{\mathrm{off}}+v_{\mathrm{low}}e_{\mathrm{low}}+v_{\mathrm{high}}e_{\mathrm{high}}.\]

Why is this true? The first term contributes only to the off coordinate, the second only to low, and the third only to high. Adding them reconstructs each original component. The coefficients are unique because no other basis vector contributes to a given coordinate.

We will also write \(|a\rangle\) for the standard basis vector associated with a label \(a\). Read this symbol as “ket a.” In this chapter it is simply convenient notation for a column vector; using a ket does not, by itself, make the description quantum. For a bit in the order \((0,1)\),

\[|0\rangle=\begin{pmatrix}1\\0\end{pmatrix},\qquad |1\rangle=\begin{pmatrix}0\\1\end{pmatrix}.\]

A definite classical bit has one of these state labels. In the next lesson, we will use weighted sums of the basis vectors to describe uncertainty. The meaning of those weights will be stated explicitly: they will be classical probabilities.

4. Number of states versus number of bits

Our three-state switch used a three-component coordinate vector. Does it therefore require three binary storage bits? No. The length of the coordinate representation and the number of bits used to encode a label are different quantities.

One bit has two possible strings, 0 and 1. Two bits have four: 00, 01, 10, and 11. In general, \(n\) bits provide \(2^n\) distinct strings because each of the \(n\) positions has two choices. To assign a different binary string to every label in a \(d\)-state set, we need

\[2^n\ge d.\]

The smallest nonnegative integer satisfying this condition is

\[n=\lceil\log_2 d\rceil.\]

If logarithms are unfamiliar, use the equivalent counting question: how many times must we double 1 before reaching at least \(d\)? The ceiling symbol means round up to the next integer. A single-state system needs no information-bearing bit to distinguish among alternatives.

Worked example: encoding the switch

For \(d=3\), one bit is insufficient because \(2<3\). Two bits suffice because \(4\ge3\). One possible code is off ↦ 00, low ↦ 01, high ↦ 10. The string 11 is unused. We must decide what an application does if that unused code appears; it should not silently acquire a fourth physical meaning.

A six-state die similarly needs at least three binary digits for a fixed-length encoding: two bits provide only four strings, while three provide eight. Two strings remain unused. Neither encoding says that the device occupies all its possible states at once. It says how many distinct labels the storage scheme can distinguish.

5. Practice and worked reasoning

Attempt these before opening the hints. They check the distinction between a system, a coordinate representation, and a binary code.

  1. A four-setting switch. Define a state set for off, low, medium, and high. Write the standard basis vector for medium in that order. How many binary digits suffice to encode the setting?
    Hint

    Assign one coordinate to each label. For the storage question, count how many strings two bits provide.

    Worked solution

    The state set is \(\{\mathrm{off},\mathrm{low},\mathrm{medium},\mathrm{high}\}\). Medium has vector \((0,0,1,0)^{\mathsf T}\). Since \(2^2=4\), two binary digits suffice. The coordinate vector has four entries even though the binary encoding uses only two digits.

  2. Changing coordinate order. Rewrite the medium vector using the order (high, medium, low, off). Explain what changed.
    Hint

    Find medium in the new list instead of moving the 1 by a memorized rule.

    Worked solution

    Medium is now the second label, so its vector is \((0,1,0,0)^{\mathsf T}\). The representation changed; the labelled setting did not. Comparing raw columns without their basis labels would be misleading.

  3. Five messages. You need a fixed-length binary code for five messages. Give a possible code and count unused strings.
    Worked solution

    Two bits give four strings, which is too few. Three bits give eight. For example, use 000, 001, 010, 011, and 100 for the messages. Three strings remain unused. The message labels still form a five-element state set, with five-component one-hot basis vectors if we choose that representation.

What to carry forward

Choose a state set and declare its order. A basis vector describes one definite label; a binary encoding stores the label using bit strings. Next we will describe uncertainty over labels with a probability vector.
